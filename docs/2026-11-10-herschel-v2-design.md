# 허셜 별 계수 시뮬레이터 v2 설계 — 튜토리얼, 언덕 관측, 지도 위 깊이 찍기, 선택형 문제

- 작성일: 2026-11-10
- 기반: `docs/2026-11-06-herschel-starcount-design.md`(v1 설계). 여기 적지 않은 내용은 v1을 그대로 따른다.
- 참고: `reference/[비상교육] 중학_과학 2_8-2_교과서-p2-3.pdf`(교과서 280~281쪽, 우리은하 구조·크기)

## 1. 의도와 이유

v1을 써 보니 세 가지가 부족했다.

1. **허셜의 규칙·가정, 특히 "별 수와 깊이의 관계"를 학생이 이해하지 못한다.** 학생은 "별이 많이 보이면 왜 은하가 더 멀리까지 이어진 거지?"부터 막힌다. 별을 세는 활동만으로는 이 연결이 생기지 않는다. 그래서 관측 전에 게임 튜토리얼처럼 직접 만지며 깨닫는 단계가 필요하다.
2. **관측 화면과 지도가 따로 논다.** v1은 우주 공간 안의 1인칭 시점이라, 학생이 바라보는 방향과 오른쪽 지도의 방향이 머릿속에서 연결되지 않는다. "망원경을 든 사람"이 화면의 주인공이 되고, 그 사람이 도는 방향이 지도와 똑같이 움직여야 한다.
3. **깊이를 숫자 버튼으로 고르면 지도를 그리는 느낌이 없다.** 학생이 지도 위 해당 방향에서 직접 깊이를 눌러 점을 찍어야 지도가 차근차근 완성되는 경험이 된다.

덧붙여 해석 단계는 자유 서술 질문을 보기만 하던 것에서, 학생이 답을 고르는 문제로 바꾼다. 마지막에는 허셜의 모형이 오늘날 알려진 우리은하와 **다르다는 점을 분명히** 짚는다.

## 2. 목표 / 비목표 / 반목표

### 목표
- 관측 전 튜토리얼(미션 4개)에서 학생이 "별이 고르게 퍼져 있으면 많이 보일수록 깊다", "깊이가 2배면 별은 8배"를 스스로 확인한다.
- 관측 화면: 밤에 언덕 위에 선 사람과 망원경. 학생이 사람을 그 자리에서 빙글 돌려 수평선 쪽 12방향을 겨누고, [관측]을 누르면 그 부분이 확대되어 별을 센다.
- 관측 화면에서 사람이 바라보는 방향과 지도 위 방향이 항상 일치한다.
- 별을 다 세면 지도의 그 방향 선이 강조되고, 학생이 그 선 위에서 깊이 1~5 중 하나를 눌러 점을 찍는다. 힌트는 튜토리얼 내용(정육면체 블록)으로 준다.
- 자동 확장은 정답 모양에서 계산하지 않고, 화면 속 별을 실제로 세어 깊이를 구한다.
- 해석 문제 7개를 한 문제씩 고르고, 바로 정답·해설을 본다. 마지막 문제에서 오늘날의 우리은하와 비교한다.
- 12방향 수치·환산표는 v1과 같고, 종이 활동지와 계속 일치한다.

### 비목표
- 학생 답 저장·제출, 점수 수집, 로그인(v1과 같음)
- 성간 먼지 효과 시뮬레이션, "별이 고르게 퍼져 있지 않다면?" 비교 실험
- 우리은하 3D 실제 모형(막대 나선) 구현 — 문제 7의 비교 그림(2D 옆모습)만 둔다
- 세로 화면 전용 레이아웃

### 반목표 (동작해도 실패로 본다)
- 튜토리얼이 길어져 관측·해석 시간이 사라진다.
- 튜토리얼이 결론을 말로 먼저 알려 주고 학생은 버튼만 누른다(직접 끌고 예상하고 확인하는 과정이 없다).
- 관측 화면의 방향과 지도의 방향이 한 번이라도 어긋나 보인다.
- 틀린 깊이가 지도에 찍혀 활동지 수치와 달라진다.
- 자동 확장이 사실상 정답을 그려 주는 연출이 된다.
- 학생이 허셜의 모형을 실제 우리은하의 모습으로 알고 수업을 마친다.

## 3. 제약 (v1에서 이어짐)

- 정적 웹앱. HTML + ES 모듈 + CSS, 빌드 도구·외부 CDN 없음, three.js 0.170.0 벤더 고정.
- 스마트폰·태블릿 가로 화면(844×390 기준) + 교사 PC 마우스.
- 학생 문구·질문·보기·해설·힌트는 `app/js/config.js` 한 곳에 둔다(선생님이 직접 고칠 수 있게).
- 별 10,000개 이하, `app/` 첫 로딩 2 MB 이하, 보급형 폰에서 부드럽게.
- 12방향 별 수 = [125,64,27,8,27,64,125,64,27,8,27,64], 깊이 = [5,4,3,2,3,4,5,4,3,2,3,4], 환산표 1→1, 8→2, 27→3, 64→4, 125→5.
- 각도 표기: 0° 오른쪽, 시계 반대 방향 증가, 90° 위(지도·활동지 공통). 0°–180° 선이 은하 기준면.
- 중2 눈높이 한국어.

## 4. 바뀌는 과학 모형의 배치 (교사와 합의)

- **12방향은 관측자의 수평선 위에 놓인다.** 사람은 언덕 위에서 망원경을 수평으로 둔 채 제자리에서 돌며 12방향을 본다. 그래서 땅에 가리는 방향이 없다.
- **지도는 "위에서 내려다본 그림"이다.** 관측자 주위 수평면을 위에서 본 것이고, 0°가 오른쪽, 90°가 위(화면 위쪽 = 관측자 기준 한 수평 방향)다. 화면의 사람이 도는 방향과 지도의 방향이 똑같이 움직인다.
- 은하는 여전히 90°–270° 축 둘레의 회전체다. 이 배치에서 은하 원반은 0°–180° 선을 품은 **세로로 선 면**이 된다. 그래서 밤하늘에서는 은하수 띠가 0° 수평선에서 머리 위를 지나 180° 수평선으로 이어지는 큰 아치로 보인다. 90°·270° 수평선 쪽은 별이 적다. (실제 밤하늘에서도 은하수가 머리 위를 가로지르는 때가 있어 어색하지 않다 — 내 판단)
- 지도에 찍히는 단면은 은하를 원반 면에 수직으로 자른 단면이다. 그래서 가로로 납작한 모양이 나오고, v1·활동지와 같다.
- 태양(관측자)은 은하 중심에 있다(허셜의 가정 그대로). 실제와의 차이는 해석 문제 7에서 다룬다.

## 5. 화면 흐름

① 도입 → ② 튜토리얼 → ③ 언덕 관측 + 지도 위 깊이 찍기(12방향) → ④ 단면 완성 → ⑤ 자동 확장 → ⑥ 해석 문제

### ① 도입
v1과 같다(탐구 문제 한 줄). 규칙·가정 목록은 글로 늘어놓지 않고 튜토리얼 안에서 하나씩 등장시킨다.

### ② 튜토리얼 (교사와 합의한 4개 미션)

각 미션은 "학생이 먼저 해 보거나 예상 → 결과 확인 → 한 줄 정리" 순서다. 정리 문장에서 허셜의 규칙·가정 이름을 붙여 준다.

1. **깊이란 무엇일까?** (2026-11-10 교사 피드백으로 숲 비유를 바꿈: "어느 숲이 깊을까?"가 무슨 뜻인지 학생이 알기 어려웠음)
   - ① 위에서 본 별 구름(타원) 한가운데에 관측자. 두 방향을 눌러 은하 끝까지 화살표가 뻗고 "깊이 5", "깊이 2"가 뜬다 → 깊이 = 그 방향 은하 끝까지의 거리.
   - ② 두 방향으로 폭이 같은 망원경 빛을 쏜다(먼저 어느 쪽이 별을 더 많이 만날지 예상). 빛이 나아가며 별을 만날 때마다 +1, 은하 끝에서 멈춘다.
   - ③ 은하 끝을 가리고 별 수만 보여 준 채 "은하 끝까지 더 먼 쪽은?"을 고른다. 맞히면 가림막이 걷힌다(허셜의 추리).
   - 정리: 가정 "별은 공간에 고르게 퍼져 있다", 규칙 "시야 크기는 항상 같다", "별을 세는 기준은 항상 같다".
2. **은하 끝 끌어 보기** — 망원경 시야를 옆에서 본 뿔 모양과, 고르게 흩어진 별, 끌 수 있는 '은하 끝' 벽. 끌기 전에 "깊이가 2배가 되면 시야 속 별은 몇 배?"를 2배·4배·8배 중 고른다. 학생이 끝을 1→2→3으로 끌면 시야 속 별이 1→8→27개로 늘고 카운터가 따라 오른다. 은하 끝 너머에는 별이 없다.
   - 정리: 가정 "망원경으로 은하의 끝까지 볼 수 있다".
3. **정육면체로 이유 보기** — 시야가 2배 길어지면 끝부분의 가로·세로도 2배 넓어진다. 블록이 1 → 2×2×2=8 → 3×3×3=27로 쌓이는 애니메이션. 이 블록 그림이 ③의 힌트로 다시 나온다.
4. **거꾸로 연습하기** — "별 8개가 보였어요, 깊이는?" 같은 문제 1~2개(별 수 → 깊이). 틀리면 미션 3의 블록을 다시 보여 준다. 끝나면 규칙 "여러 방향으로 망원경을 돌려 관측한다"를 소개하며 언덕 장면으로 넘어간다.

- 수치(1·8·27, 2배→8배)는 v1 환산표와 같다.
- 튜토리얼 '건너뛰기'는 교사 시연용으로 작게 둔다(내 결정).

### ③ 언덕 관측 + 지도 위 깊이 찍기

**화면 배치(가로)**: 왼쪽 큰 영역 = 관측 장면, 오른쪽 = 지도(항상 보임). 기록표는 지도와 같은 패널 안에 접거나 작게 둔다(배치는 빌더 재량, 단 지도가 주인공).

**관측 장면**
- 밤하늘 아래 언덕 위에 사람과 망원경. 별이 사방에 펼쳐져 있고, 은하수 아치가 보인다.
- 학생이 화면을 좌우로 끌면 사람이 제자리에서 돈다. 망원경은 늘 수평선 쪽을 겨눈다.
- 12방향 목표가 수평선 위에 표시되고, 가까이 가면 맞춰진다(스냅). 맞춰지면 [관측] 버튼.
- [관측]을 누르면 망원경 시야 부분이 확대된 접안렌즈 화면이 열리고, 별을 탭하거나 자동 세기로 센다(10개 초과면 자동 세기 — 2026-11-10 교사 요청으로 30에서 낮춤: 27·64·125개는 자동, 8개는 직접. 다 세야 끝).
- 확대 화면에 보이는 별은 실제로 그 방향 시야 원뿔 안에 있는 별이며, 개수는 12방향 표와 정확히 같다.
- 관측 장면의 시점(사람을 뒤·위에서 보는 3인칭 등), 사람과 망원경의 그림 방식(3D 모델·스프라이트·단순 도형)은 빌더 재량. 단, 사람이 바라보는 방향이 지도의 강조 선과 같은 쪽으로 보여야 한다.

**지도 위 깊이 찍기 (교사와 합의)**
- 별을 다 세면 오른쪽 지도가 **화면 가운데로 크게 날아와 펼쳐지고**, 나머지 화면은 어두워진다. 위에 "지도에 점을 찍어요!" 띠가 뜬다(2026-11-10 교사 결정: 점을 찍어야 한다는 것이 바로 보이게).
- 그 방향 선이 노랗고 두껍게 강조되고, 선 위 깊이 1~5 자리에 후보 동그라미가 깜빡인다. 맞는 점을 찍으면 지도가 오른쪽 자리로 돌아가며 점이 남는다.
- 학생이 후보 하나를 누르면 점이 찍히고, 기록표에 별 수·깊이가 기록된다.
- 힌트 카드는 큰 지도 옆에 붙고, 숫자 환산표 대신 튜토리얼의 블록 그림으로 묻는다. 예: "별 64개 = □×□×□인 상자. 한 변은 몇 칸?"
- 틀리면:
  - 첫 번째: 블록 힌트를 한 단계 더 자세히 보여 준다(예: 4×4 한 층 그림).
  - 두 번째: 튜토리얼에서 본 '깊이 ↔ 별 수' 짝(1↔1, 2↔8, 3↔27, 4↔64, 5↔125)을 보여 준다.
  - 틀린 점은 지도에 남지 않는다.
- 관측 장면에도 그 방향으로 깊이만큼의 표시(선·점)를 남겨 둔다(빌더 재량, 단 은하 모양을 미리 드러내지 않을 것).

### ④ 단면 완성
12방향이 다 찍히면 지도의 점이 이어져 단면이 된다. 관측 장면은 바깥 시점으로 물러나 학생이 찍은 점·선만 보인다(별 숨김, v1과 같음). 사람·언덕은 아주 작게 줄이거나 태양 표시로 바꾼다(빌더 재량).

### ⑤ 자동 확장 (과학 검토 결과 반영)

**검토 결과**
- 한 평면의 단면을 3D 원반으로 넓히는 것은 허셜의 결론("납작한 맷돌 모양")과 맞다. 문제없다.
- v1의 오류: 다른 방향의 깊이를 **미리 정해 둔 은하 모양에서 계산**해 찍었다. 학생에게는 관측처럼 보이지만 실제로는 정답을 그려 주는 셈이고, 허셜의 방법과도 다르다.

**v2**
- 방향마다 그 방향 시야 원뿔 안의 별을 **실제로 세고**, 깊이 = 별 수의 세제곱근으로 구해 점을 찍는다. 화면 속 별은 은하 안에 고르게 흩어져 있으므로, 결과는 원반 모양이 되면서도 방향마다 조금씩 들쭉날쭉하다. 이것이 진짜 관측답다.
- 12방향(학생 측정)은 v1처럼 표의 수치와 정확히 같다.
- 수평선 아래 방향은 언덕에서 볼 수 없으므로, 자동 확장 중 아래쪽 하늘은 "지구 반대편(남반구)에서 관측한 하늘"로 안내한다(내 결정). 위쪽 하늘만 언덕에서 잰다.
- 은하 표면은 학생 12방향 + 자동 측정값을 방향별로 그대로 이어 만든다(2026-11-10 검토: 고도별 평균 후 회전시키면 허셜이 하지 않은 '회전 대칭' 가정이 들어가므로 뺌).
- 바깥 시점에 '실제 모습이 아님' 이름표 창을 띄웠다가 교사 요청으로 뺐다(화면을 가림). 대신 안내 문구와 [가상 은하의 별 보기] 버튼 이름으로 알린다.
- 방향 수·순서·속도, 노이즈를 보여 주는 방식은 빌더 재량. 전체 연출은 수십 초 이내, 건너뛰기 가능(v1과 같음).
- 별 수를 세는 시야 원뿔은 12방향과 같은 크기(반각 10°)를 쓴다. 규칙 "시야 크기는 항상 같다"와 일치해야 한다.

### ⑥ 해석 문제 (교사와 합의)

- 문제 7개를 **한 문제씩** 넘긴다. 보기를 고르면 바로 ⭕/❌와 짧은 해설을 보여 주고, [다음]으로 넘어간다. 틀려도 해설을 보고 넘어간다. 마지막에 맞힌 개수를 보여 준다(저장하지 않음).
- 해석 단계에서도 3D 지도는 돌려 볼 수 있다(v1과 같음).

| 번호 | 영역 | 문제 | 보기 (✓ 정답) |
|---|---|---|---|
| 1 | 방법 돌아보기 | 우리는 은하 밖으로 나가지 않았는데 어떻게 은하의 모양을 알아낼 수 있었을까? | ✓여러 방향의 별 수를 세어 방향마다 은하의 깊이를 비교했다 / 은하 전체 사진을 찍었다 / 별까지 거리를 자로 재듯 직접 쟀다 / 별의 색을 비교했다 |
| 2 | 관측 결과 분석 | 별이 가장 많이 관측된 방향은? | ✓0°와 180° / 90°와 270° / 30°와 210° / 모든 방향이 같다 |
| 3 | 관측 결과 분석 | 별이 가장 적게 관측된 방향은? | 0°와 180° / ✓90°와 270° / 60°와 240° / 모든 방향이 같다 |
| 4 | 관측 결과 분석 | 허셜의 가정대로라면, 별이 많이 관측된 방향은 적게 관측된 방향과 무엇이 다를까? | ✓은하가 더 멀리까지 이어져 있다 / 별이 더 밝다 / 별이 더 가까이 있다 / 우연이라 차이가 없다 |
| 5 | 과학적 추론 | 별이 많이 관측된 0°–180° 방향으로 은하는 어떻게 이어져 있을까? | ✓양쪽으로 길게 퍼져 있다 / 금방 끝난다 / 한쪽으로만 길다 / 알 수 없다 |

| 7 | 오늘날의 우리은하와 비교 | 오늘날 알려진 우리은하와 비교할 때, 허셜의 모형에서 틀린 점은? | ✓태양이 은하의 중심에 있다고 했다 / 은하가 납작한 원반 모양이라고 했다 / 별들이 한데 모여 은하를 이룬다고 했다 / 은하수가 띠 모양으로 보인다고 했다 |

- 문제 7 화면에는 두 그림을 나란히 둔다: **허셜의 모형**(납작한 원반, 태양이 한가운데)과 **오늘날 알려진 우리은하 옆모습**(중심부가 약간 부푼 원반, 태양계는 중심에서 약 8500 pc, 지름 약 30000 pc). 수치와 표현은 교과서 280~281쪽과 같다(교사 확인).
- 문제 7 해설은 "납작한 원반이라는 점은 맞았다"와 "태양(태양계)은 중심이 아니라 중심에서 약 8500 pc 떨어진 곳에 있다"를 함께 말한다. 그래서 학생이 허셜의 모형을 실제 모습으로 알고 끝나지 않게 한다. (v1 비목표 "실제 우리은하 공개 안 함"을 이 문제에 한해 바꾼다 — 교사 결정)
- 보기 순서는 화면에서 섞어도 된다(빌더 재량). 해설 문구는 빌더가 중2 눈높이로 쓰고 `config.js`에 둔다.
